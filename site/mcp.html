MCP

Every desk is an MCP server. An assistant with a token can make and rename pages, place cards, schedule when a screen turns to a page, set alarms, calendars, world clocks and location, and fill in accounts. Screens pick up changes within a few seconds.

Connect

  1. On your desk, open Settings → MCP.
  2. Name a token, pick what it can do and, if you like, which screens it may touch. Make a token: it’s shown once, with the lines to paste.
  3. Give your assistant the server address https://your-desk/api/mcp and the token.

Claude Code

claude mcp add --transport http archers-desk https://your-desk/api/mcp \
  --header "Authorization: Bearer desk_…"

Claude Desktop, Cursor and other config-file clients

{
  "mcpServers": {
    "archers-desk": {
      "type": "http",
      "url": "https://your-desk/api/mcp",
      "headers": { "Authorization": "Bearer desk_…" }
    }
  }
}

Claude.ai and ChatGPT

Add a custom connector with the server address and the token as a bearer Authorization header. These reach your desk from the internet, so it needs a public https address.

The server speaks Streamable HTTP without sessions or a stream: each request is answered on its own. Every account shares the one address; the token decides whose desk it is.

Scopes and screens

A token only sees the tools its scopes allow.

readSee screens, pages, alarms, calendars and which accounts are set up. Never secrets.
screensPages, cards, set times, location, away and each screen’s own options.
alarmsAdd, change and remove alarms.
calendarsAdd, change and remove calendar feeds.
timeWorld clocks and units.
accountsUsernames, addresses and keys widgets sign in with. Keys can be written, never read back.

A token can be kept to some screens. It then sees and changes only those; sees alarms that ring on them and changes only the ones that ring on nothing else; and can’t make new screens. Calendars, world clocks, units and accounts belong to the whole account and follow the scopes alone. Revoke a token in Settings → MCP and it stops on its next request.

How a desk is shaped

Screen
A display the desk runs on. Each has its own pages and location.
Page
Screens swipe through Standby, then their pages, then the Pad (if a Mac pad is set up). Pages are numbered from 1 and can be named; tools take either.
Row and card
A page is rows, swiped up and down. A row is two squares, {"left", "right"}, or one wide card, {"wide"}. list_widgets names every card.
Set time
A screen turning to a page at a time: every day, some days, or once on a date. With stay_minutes it goes back afterwards, unless someone touched it.
Idle return
After someone turns the page and leaves, the screen goes back to a page once it’s been untouched for a while.

Example: a working day

create_page   {"name": "Programs", "rows": [{"left": "phantom_active", "right": "phantom_people"}, {"wide": "phantom_money"}]}
add_set_time  {"at": "10:30", "show": "Programs", "days": ["mon","tue","wed","thu","fri"]}
add_set_time  {"at": "16:15", "show": "Programs", "days": ["tue"], "stay_minutes": 60}
add_set_time  {"at": "16:45", "show": "Programs", "date": "2026-10-22", "stay_minutes": 45}
set_idle_return {"after_minutes": 15, "to": "standby"}

REST and OpenAPI

Every tool is also POST /api/v1/<tool> with the arguments as the json body and the same token. It answers {"result"}, or {"error"} with a 400 (fix the request), 401 (no token) or 403 (outside its scopes or screens). 

curl -X POST https://your-desk/api/v1/add_set_time \
  -H "Authorization: Bearer desk_…" -H "content-type: application/json" \
  -d '{"screen": "main", "at": "16:15", "show": "Phantom", "days": ["tue"], "stay_minutes": 60}'

The OpenAPI 3.1 description is here, and every desk serves its own at /openapi.json with its address filled in. Each desk also has this guide at /docs.
